# 验证约束

默认只允许最小验证。验证是成本，不是流程。禁止无用户明确指令的构建（debug / release）版本。

## 允许验证的唯一条件

同时满足：
1. 已做出改动（只读/分析/建议/文案注释文档 → 禁止验证）
2. 改动影响交付结论
3. 有明确的结论消费方
4. 本机环境做得了

任一不满足 → 零验证。环境做不了 → 声明盲区 + 指明谁验证，不重试、不降级乱试。

验证前必须先报出四问判定（一句话），无判定句不得调用任何验证命令。

四问判定模板（照抄填空，缺一项就不验）：

> 本轮验证：① 改动 = <文件+行为变化>；② 影响 <哪个交付结论>；③ 消费方 = <谁读这个结论>；④ 本机可验（<命令>）。

反例（曾真实发生，禁止重演）：改动只是删了一条 `box-shadow` 或改注释排版 → ②③ 全空 → 不验。

## 范围绑定（选错即错）

| 被改的代码库 | 适用 |
|---|---|
| 用户项目 | A + C |
| agent 自身项目 | B + C |
| Nuphus 仓库 | D + C |

互不通用。

## A. 用户项目

- 改哪层测哪层：改 L1（语法）只跑语法；改逻辑跑语法+类型+单测。禁止习惯性全量、禁止跑与改动无关的检查。
- 格式/静态检查（fmt / prettier / tsc）是全局契约，必须全量跑，禁止只查改动的文件。
- 工具缺失 → 声明盲区，禁止假装测过。
- 测不了（平台/硬件/外部依赖/规模/真人判断/真机交互）→ 交 CI / 真机 / 联调环境 / 用户，指明验证方后停下。禁止在测不了的层反复试。
- 产物被运行中进程锁定：停不了 → 声明交 CI，不绕过。
- 单个用例卡死 → 精确 skip，禁止整轮重跑。

## B. agent 自身项目

- 只增量 `cargo check`，禁止 build。
- 多处改动攒一批一次验。
- 禁止新建 target；target 被占用 → 报告用户定时机。
- `--target-dir` 指向新路径等同新建 target；自建路径用完必须立即删除并报磁盘变化。
- 同一策略连失败 3 次 → 停，换路径。
- 禁止数据副本/临时环境变量/降断言造假绿。

## C. 执行纪律

- 任务 >2 分钟：优先后台 + 落盘 + 轮询；若工具无后台模式，则**一次给足超时同步等待**，禁止中途杀掉重来（长任务的已完成成果会全部作废）。
- 等待远程事件（CI / 网络 / 第三方）禁止循环 sleep 空转，单次查询后交还控制权。
- shell 超时上限 1800s。**超时是否杀子进程按任务分层**（见 `sub_task_shell.rs` 的 `LONG_TASK_THRESHOLD_SECS`）：
  - `timeout` ≤ 300s（普通命令）→ 杀掉止损，卡死的命令不该继续占资源；
  - `timeout` > 300s（构建 / 全量测试 / 大下载）→ **不杀**，杀掉等于让下次从零重跑。此时回报「仍在后台运行 + 勿重复执行」，用 sleep 后读输出文件收结果。
  - 一律不杀是错的（会泄漏卡死命令），一律杀也是错的（会作废长任务成果）。
- 命令莫名挂起：禁用 `-PassThru -NoNewWindow`；杀进程不加管道。
- 同一策略连续失败 2 次 → 停下来重审，不要凑第三次。

## D. Nuphus 仓库

- `cargo check -p <crate>` 确认编译；**禁止全量 `cargo build` / `--release` 产物构建**（release link 慢且与逻辑验证无关）。
- 改逻辑 + 加/改测试后，允许精确到模块跑 `cargo test -p <crate> --lib <模块路径>`；**多处改动攒一批一次验**，禁止每个小改动跑一轮。
- 注释 / 文案 / 排版类改动（零行为影响）→ 禁止跑构建验证，纯属堆验证数量。
- 被运行中 nuphus.exe 锁定 → 报告用户定时机，禁 kill 自身。
- 桌面自动化/UIA → 真机或 `#[ignore]`。
- CI 失败先归因三分：代码 / 环境 / 配置；归因到环境不得改代码绕过，网络类先重试。
- 推送前本地只跑 CI 主干同项：fmt + tsc + prettier 全量，其余不跑。

## 禁止

1. 未改动先验证
2. 为验证而验证 / 堆验证数量
3. 给零消费方的产物做验证
4. 本机限制当任务结论
5. 章节误用
